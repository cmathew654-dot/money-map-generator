# Constraints

## Canvas-First Editor Implementation Plan
- source: docs/superpowers/plans/2026-08-02-canvas-first-editor.md
- type: nfr
- content:
  Architecture contract for the s42 rebuild: `App.tsx` remains sole owner of book, client, history, persistence, writer, selection, and panel state. Existing `Form`, `Wizard`, `MapSvg`, `MapInspector`, `mapInteraction`, book/layout/history helpers stay authoritative; new UI components (`EditorRail.tsx`, `EditorPanels.tsx`, `ClientCombobox.tsx`) are callback-only and never hold a second `MoneyMapData` snapshot. No new dependency. Every model mutation routes through `handleClientChange`/`handleMapChange` and produces one history entry. Delivered as 7 TDD tasks: (1) pointer-ownership cleanup, remove implicit text dragging, remove "Snap to alignment"; (2) rail + on-demand Data panel shell, CSS grid `72px minmax(0,380px) minmax(0,1fr)`; (3) make Data (`Form.tsx`) complete/searchable/selection-synced via new `filter`, `activeSection`, `onSectionFocus` props — explicitly "reuse Form; do not create a second editor"; (4) Add/Contents/Help panels in `EditorPanels.tsx`; (5) multi-selection, alignment/distribute, internal clipboard; (6) `ClientCombobox`, connector handles; (7) integration, responsive/a11y/visual certification. Present/print/PNG/PDF/SVG must contain no editor chrome.

## Canvas-First Editor Design
- source: docs/superpowers/specs/2026-08-02-canvas-first-editor-design.md
- type: nfr
- content:
  Status: "Approved direction. This specification supersedes the left-editor and inspector-alignment portions of `2026-08-02-editor-tidy-design.md`." Replaces the permanent 420px form pane with 5 persistent zones: Header, 72px Editor rail (Add/Data/Contents/Help), Canvas, Contextual inspector, Canvas toolbar. Add/Data/Contents share one 380px panel next to the rail (opening one closes the others); below 1180px (or equivalent zoom) it overlays instead of pushing the map. Guide me/Full form toggle removed from normal workflow.
  **Data panel** (directly relevant to the planned Form.tsx redesign): "the complete, explicit answer to 'where do I enter this?'" — every existing financial field, preserves null money as blanks. Sections: Client, Income, Accounts, Need, Fine print, Notes. Has a sticky section navigator and a filter matching section/account/income-source/field labels; filtering never changes map data. Selection syncs bidirectionally between canvas and Data (Details opens Data to the right section; closing Data leaves canvas selection intact). All fields update the canonical `MoneyMapData` owned by `App`; a panel may hold a focused display draft only while its input is focused — clear/reset/undo/client-switch/writer-handoff must cancel obsolete drafts.
  Add panel groups creation by financial meaning (income source, account, monthly need, flow, text note, fine-print line). Contents is a searchable outline (Income/Need, Accounts, Flows, Notes/fine print), not a layers system. Contextual inspector stays the selection-specific quick-actions surface; "Details" is the only path into exhaustive editing — inspector "must not become another full form."
  Pointer/selection model: text hover = underline + text cursor (no card shadow); text click = edit; card-body hover = quiet outline + grab; card-body drag = move whole card; canvas-background drag = pan only when zoomed. Editable account text is not freely draggable by default — moving its offset requires an explicit "Move text" inspector action. "Snap to alignment" button removed entirely; drag-time snap guides + multi-select align/distribute (Shift/Ctrl/Cmd-click) replace it. **Tidy map** stays a map-level command that removes manual overrides and restores the deterministic generated arrangement (later redefined by editor-stabilization-design, see WARNING in conflicts report).
  State constraints: `App` sole owner of book/client/history/writer/persistence/selection/panel state; no new runtime dependency, context provider, or state framework; content edits and layout edits stay separate in the model. WCAG 2.2 AA, forced-colors, reduced-motion preserved; Present/print/export strip all editor chrome.

## Editor Stabilization Design
- source: docs/superpowers/specs/2026-08-03-editor-stabilization-design.md
- type: nfr
- content:
  "Make the advisor canvas predictable in live meetings without redesigning the data model or editor." Selection/inspector: inspector stays visible during inline text editing regardless of voice input/focus changes; click opens inline edit; drag-threshold moves the owning item; text hit areas fit rendered text (not a % of parent shape); one direct resize handle on the selected account/income/need/note (absent in Present/export). Notes: armed placement accepts any map point including over a shape (placement wins over selection); new note selected immediately; adds optional `font: 'serif' | 'sans'` (default serif). Amount notes/warnings: `qualifier`/`valueTag`/`needTag` stay in saved JSON for compatibility but are hidden from editor and canvas; all warning UI (global banner, Contents warnings, badges, wizard warning state) hidden — no data migration deletes values.
  **Tidy map redefinition**: becomes a conservative 12-unit anchor snap (not a reset) preserving sizes/rotations/text offsets/composition; re-routes generated connectors; one undo step; no-op when already snapped; `Reset arrangement` becomes the separate command for full generated-layout restore; feedback text "Map aligned to grid." — this narrows/changes the "restores the deterministic generated arrangement" Tidy behavior defined in canvas-first-editor-design.md.
  **Left editor polish** (CSS-only, explicitly "not a navigation rewrite and adds no new component system"): "Keep the existing 420 px panel, tabs, state ownership, and workflows" — reduce uppercase micro-labels/boxed styling, tighten vertical rhythm, shrink Details/Duplicate/shape-selector/inspector controls, retain Public Sans (controls) / Literata (map values). NOTE: the companion implementation plan (`2026-08-03-editor-stabilization.md`, Task 5 Interfaces) disambiguates this as two coexisting panels — "420 px guided panel, 380 px editor panel" — i.e. the Wizard's guided-setup panel stays 420px, the canvas-first Data panel stays 380px per canvas-first-editor-design.md. See WARNING in the conflicts report: the design doc's own prose does not make this distinction explicit.
  Explicitly out of scope: removing after-tax/gross/account-type data, changing income calculations, automatic collision avoidance during Tidy, rich-text notes/arbitrary colors, new dependencies/state owners/context providers/migrations.

## Guided-Freeform Build Flow Design
- source: docs/superpowers/specs/2026-08-03-guided-freeform-build-flow-design.md
- type: nfr
- content:
  Replaces the Add panel's toolbox framing with a "Map setup" readiness checklist (income sources, accounts, monthly need, flows, notes) that reflects readiness, not required sequence — "Adding an account first is fully supported; adding income first is fully supported; setting monthly need first is fully supported." First incomplete essential becomes the recommended action; nothing else is blocked. Adding any item focuses its corresponding Data fields. No modal wizard, forced ordering, or hidden capability. Top-bar hierarchy: left = wordmark/client identity, center = undo/redo, primary-right = Present/Print/Export, overflow = New client/Book/Reset/recovery. Scope: `src/ui/EditorPanels.tsx`, `src/App.tsx`, `src/styles/app.css`; no new dependency or state-owner change.
