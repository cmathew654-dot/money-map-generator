# s51 A1b — shift-click collapsed the selection with the Data panel open

## Root cause

`onSelectAccount` — `src/App.tsx:2152` (was `setSelectedMapTargetKey(...)`).

With the panel open, every map click also runs App's `editorPanel === 'data'`
branch (`App.tsx:1335`) -> `focusDataTarget` -> the focus effect
(`Form.tsx:1037`) focuses the row's first field -> `onFocusCapture`
(`Form.tsx:881`) reports that account back as a selection — via
`setSelectedMapTargetKey` = `setSelectedMapTargetKeys(key ? [key] : [])`
(`App.tsx:472`), the SINGLE-key setter. A shift-click that had just extended
`[A, B]` was narrowed to `[B]` in the same tick. MapSvg's
`nextSelectedTargetKeys` decided correctly; the panel overwrote it.

## Diff

- `src/App.tsx:151-161` — new exported pure `panelSelectionKeys(keys,
  accountId)`: keeps a selection already holding `account:<id>`, else selects
  it alone. Same array identity on a no-op.
- `src/App.tsx:2152` — `onSelectAccount` routes through it.

MapSvg untouched, and `selectedAccountId` still derives from
`selectedMapTargetKeys.at(-1)` — the account shift-click just added — so the
panel's focus, scroll and T-FORM auto-expand all still fire. Pre-existing and
unchanged: a modifier-click that DEselects still focuses that row.
