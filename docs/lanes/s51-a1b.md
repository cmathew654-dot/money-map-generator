# s51 A1b — shift-click collapsed the map selection with the Data panel open

## Root cause

`onSelectAccount` — `src/App.tsx:2152` (was `setSelectedMapTargetKey(...)`).

With the Data panel open every map click also runs App's `editorPanel ===
'data'` branch (`App.tsx:1335`) -> `focusDataTarget` -> `AccountsSection`'s
focus effect (`Form.tsx:1037`) focuses the row's first field ->
`onFocusCapture` (`Form.tsx:881`) reports that account back as a selection.

That report went through `setSelectedMapTargetKey` = `setSelectedMapTargetKeys(
key ? [key] : [])` (`App.tsx:472`) — the SINGLE-key setter. A shift-click that
had just extended `[A, B]` was narrowed to `[B]` in the same tick. MapSvg's
`nextSelectedTargetKeys` decided correctly; the panel overwrote it.

## Diff

- `src/App.tsx:151-161` — new exported pure `panelSelectionKeys(keys,
  accountId)`: keeps a selection already holding `account:<id>`, else selects
  it alone. Same array identity on a no-op.
- `src/App.tsx:2152` — the panel's `onSelectAccount` routes through it via the
  functional `setSelectedMapTargetKeys` updater.

MapSvg is untouched, so the canonical click decision still owns selection. The
panel is unchanged: `selectedAccountId` derives from
`selectedMapTargetKeys.at(-1)`, which shift-click leaves on the newly added
account — focus, scroll and the T-FORM auto-expand all still fire.

Not fixed (needs a modifier flag on `MapElementTarget`, i.e. MapSvg): a
modifier-click that DEselects an account still focuses its row, collapsing onto
it. Pre-existing, unchanged here.
