States

S0 · Reference start

One photograph: a CRT on a dark desk, a design studio behind it, golden-hour light. The brief was 1:1 fidelity in Blender.

S1 · Procedural Blender scene done

4,774 lines of Python that generate every mesh and every material. No downloaded assets, no image textures. Renders in Cycles to a 1600×900 still.

How
  • No Blender binary — download.blender.org was blocked by the session's network policy, but PyPI wasn't. pip install bpy==5.2.1 gave a full headless Blender.
  • The CRT is lofted from superellipse cross-sections: that's what gives a real tube its boxy face, straight sides and hard taper. A rounded cube never reads right.
  • The screen is ~400 emissive plates and text objects on a virtual 640×480 raster, so the interface lights the desk. Not a texture.
  • Camera matched by measuring the monitor and doorway as fractions of the reference frame and solving for focal length and distance: 24mm, 0.86m back, near desk height.
Learned
  • Linearise emission colours. Feeding sRGB straight into emission made navy glow like white. Once linearised, the screen had real contrast.
  • Blender 5's compositor needs a GPU. Bloom and vignette moved to a numpy pass on the linear EXR, which is a better place for them anyway.
  • A helper that force-smoothed every face turned the monitor into a pillow. Shading flags are per-surface decisions.
  • Khronos PBR Neutral over AgX for this brief — AgX desaturates emissive highlights, and the reference is saturated.

S2 · Walkable browser scene, live page in the CRT done

The scene exported to glTF and running in three.js: WASD and touch controls, and the monitor showing a real, clickable <iframe>. Published as a single 6.85 MB HTML page.

How
  • CSS3DRenderer puts a DOM element in the same 3D space as WebGL; a depth-only plane on the screen's transform punches a hole in a transparent canvas so the DOM shows through and the bezel still occludes. Decade-old technique, verified here by clicking inside the iframe headlessly.
  • Artifacts can't fetch external files, so three.js is esbuild-bundled (577 KB) and the GLB is meshopt-compressed by gltfpack (11 MB → 1.6 MB) and base64-inlined.
  • CRT_ScreenFace is split out of the monitor as a named, unit-UV plane — the anchor the runtime positions the iframe against.
Learned
  • Never export Blender's lights to glTF. They arrive in physical units — sun at 5,327 lux, lamp at 6,413 cd — and rendered the whole room white. I blamed software rendering twice before exposing a debug handle and asking the live scene what lights it had.
  • glTF can't carry a node graph. Seven procedural materials — desk, floor, brick, plants — exported as white. Flat fallback colours now, baked albedo is the real fix.
  • movementX is empty for touch pointers; three.js fov is vertical so portrait crops to a sliver; Blender +Y is three.js −Z. All found by testing at iPhone size.
  • A passing automated test is not a usable page. Playwright clicked a button that was invisible to humans because #modes lacked position:fixed. "How do I walk on iOS" caught it.

S3 · Baked lighting current

The 15 large surfaces — floor, ceiling, every wall, the desk — carry Cycles COMBINED bakes on a second UV channel and draw unlit. Props are lit by five hand-placed runtime lights. This is what's live at the link now.

How
  • Lightmap UVs via smart-project on exact-named surfaces; Cycles bakes at 768px/48spp; textures saved as JPEG; each material becomes a flat lookup of its bake through the Lightmap UV; runtime swaps to MeshBasicMaterial.
  • All 954 props were also vertex-baked (COMBINED into a Baked colour attribute) and the data is in export/work.blend.
Learned
  • This container suspends background processes when the session idles. Two bakes died within minutes of the conversation going quiet — not OOM, not a crash. Long jobs must be resumable: write per-item, skip finished, stop on a time budget. Both bakes then completed in foreground chunks with zero failures.
  • A "Back_" prefix meant for three walls caught 54 props. Match on exact names.
  • The vertex bake is a regression and is switched off. A 20-sample COMBINED bake on a prop with a handful of vertices carries almost no signal; gltfpack's simplification and 8-bit colour quantisation finish it. The wall wedge is one triangle and came back black.
  • GLTFLoader enables vertexColors whenever COLOR_0 is present, so merely shipping the attribute darkens every albedo. Export it off by default.
  • A cyan "screen spill" light 30cm from the keyboard behaved like 18× its nominal value and tinted every beige surface mint. Inverse-square is unforgiving up close.

S4 · The demo as intended next

Approach from the street, walk in, sit at the desk, see the client's real website on the CRT. Works on an iPhone.

Build
  1. Exterior. Street, storefront, door, and a walk-in path. Nothing exists yet and it's the framing device for the whole piece. Real modelling, in scene/, same procedural approach.
  2. Real site in the CRT. Change the iframe URL. Confirm the site doesn't send X-Frame-Options: DENY or a tight frame-ancestors CSP.
  3. Hybrid screen, refined. A screenshot texture of the site at distance; when seated the camera is locked, so a plain 2D iframe positioned over the screen rect works identically to the CSS3D one — and removes the only iOS-fragile dependency (a 3D-transformed iframe) instead of testing for it. Reviewer's idea; better than mine.
  4. Fix the lightmap grade. Bakes are 8-bit PNG with no view transform, so highlights clip and the room drifts from the still. Bake to float, or apply exposure before saving. Then KTX2/Basis for iOS memory.
  5. Host it on the marketing site, not as a Claude artifact. Serve the GLB and textures as separate cached files rather than base64 in the HTML — the inlining exists only because the artifact sandbox can't fetch. Self-hosting also dissolves the cross-origin question for the client's own site.
  6. Physical iPhone test. Everything mobile so far ran in Chromium with an iPhone user agent, not WebKit. Thirty seconds on a real device.

S5 · End state goal

A polished, walkable studio on the client's website. Visitors arrive on the pavement, cross the threshold, and end up at a 1997 desk looking at the client's current site inside a CRT. Loads in under 5 seconds on cellular, holds 60fps on a laptop and 30+ on a phone, and reads as a portfolio piece in its own right.

Optional
  • Hotspots on props — books, posters, the mug — that open real work.
  • USDZ export → AR Quick Look on iOS, for free from the same Blender scene.
  • Redo the vertex bake properly (subdivide, more samples, no decimation) or lightmap the largest props individually; either removes the last five runtime lights.

Is the handoff pointed the right way?

A second model reviewed the repo and both docs adversarially before this was finalised, with one instruction: treat it as a working system to harden, not a proposal to tear down. Its answers, in order of how much they mattered:

  • Architecture — yes. "three.js + CSS3D is the right stack; nothing in the end goal needs another engine." No re-platforming. Two refinements, both adopted above: the flat iframe when seated, and separate cached asset files for real hosting.
  • Rebuildability — no, and now fixed. The still was reproducible; the baked GLB and the web page were not, because the actual sequence lived outside the repo and webexport.run() did something different and broken. Both now rebuild from a clone, verified.
  • Honesty of the handoff — mostly, with corrections. It said "change iframe.src" (it was srcdoc); said "cap lightmaps at 1024²" (they were 768, and the real issue is 8-bit clipping); and presented Chromium-with-a-UA screenshots as iOS. All three corrected. The acknowledged gaps — vertex bake off, exterior missing, artifact-vs-hosting — were confirmed accurate.
  • Fragilities worth knowing (open, documented): screen-plate hiding is a geometric heuristic; camera clamps and fog are interior-only constants that the exterior will break; the GLB decodes synchronously at load.

Net: the direction was right, the code was mostly right, and the handoff was overstating reproducibility. That last one is the failure mode that costs the next person a day, and it's the one a second pair of eyes is for.

Decisions that held, decisions that flipped

Procedural over assets

Held. A parametric scene is a set generator, not a prop. Every fix so far was a code change, not a remodel.

Bake, don't simulate

Held. The room lights itself in the browser with zero realtime lights on the statics. The props are the only holdout.

three.js over Unreal

Held, and strengthened once the goal became "in the browser". Unreal in a browser is pixel streaming — a GPU per visitor.

Vertex-bake the props

Flipped. Baked successfully, looked worse, switched off. Needs subdivision first.

Export lights and vertex colours

Flipped to off-by-default. Both silently wrecked the render when present.

Background jobs

Flipped. Nothing long runs unattended here. Everything long is now resumable.
