# Adversarial handoff review — 6 Sep 2026

Second-model review of the repo and handoff, run before finalising. Findings
verified against the code by the primary author; every item below was either
fixed in the following commit or is called out in the handoff as open.

## Fixed in the next commit
- `webexport.run()` ran `flatten_procedural_colors()` before the albedo bake
  (severing the links it reads) and never applied lightmaps. Reordered.
- `apply_lightmaps(as_jpeg=True)` was a no-op: `Image.file_format` does not
  affect glTF embedding. Now `export_glb(image_format="JPEG")`.
- `export_glb(draco=True)` was a silent no-op under pip `bpy`; default off.
- Web build tooling (`assemble.py`, esbuild, gltfpack flags) lived only in a
  scratchpad. Now `web/build.py` + `web/package.json` + `web/shell.html` +
  `web/src/app.js`; stale `web/index.html`/`main.js`/`vendor/` removed.
- Fonts were hard-coded Linux paths; on Windows every text object fell back
  silently. Added Windows/mac Arial paths (metric-compatible), a
  `CLOVER_FONT_DIR` override, and a warning on fallback.
- Handoff said "change `iframe.src`" — it was `srcdoc`. `SITE_URL` constant added.
- `btn-sit` showed "Esc" on phones after toggling. Fixed.
- `window.__dbg` shipped in production. Now behind `?debug`.
- No `requirements.txt`; README referenced a `blender/` dir that no longer exists.

## Confirmed direction
three.js + CSS3D is right; nothing in the end goal needs another engine.
Two refinements adopted into the roadmap:
1. When seated the camera is locked, so a plain 2D-positioned iframe over the
   screen rect (with a screenshot texture at distance) removes the only
   iOS-fragile dependency — the 3D-transformed iframe.
2. For the marketing site, serve GLB + KTX2 as separate cached files, not
   base64 in the HTML.

## Still open (acknowledged)
- Lightmaps are 8-bit PNG with no view transform; highlights clip, grade
  diverges from the still. Bake to float or apply exposure before saving.
- Screen-plate hiding uses a bounding-sphere heuristic; fragile on scene change.
- `placeScreen` uses a world AABB; wrong if the CRT rotates much past −2.5°.
- Camera clamps, fog and far plane in `app.js` are interior-only constants.
- iOS screenshots came from Chromium with an iPhone UA, not WebKit.
- 6 MB base64 GLB decodes synchronously on the main thread at load.
- `export/albedo/*.png` are produced but nothing consumes them yet.

## Ranked risks → cheapest test
1. Page can't be rebuilt from a clone → fresh clone, `cd web && npm install && python build.py`
2. Client site blocks framing → `curl -sI <site> | grep -iE 'x-frame|frame-ancestors'`
3. iOS perf (alpha canvas + CSS3D + backdrop-filter + DPR-2 MSAA on 318k tris) → real iPhone over LAN
4. Lightmap grade mismatch → side-by-side at the still's camera
5. Windows font fallback → build once on Windows, compare wordmark
6. Exterior breaks interior-only constants → place camera outside
